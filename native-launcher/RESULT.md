在同一台机器、同一份已同意声明的 QA 配置中，关闭调试端口和测试用浏览器参数，分别测量三个连续启动：旧版显示主界面的中位数为 3,773 ms，新版为约 1,700 ms。该环境关闭了系统动画；结果不包含首次安装运行时、第一次建立浏览器缓存或首次阅读声明的时间，也不保证其他电脑耗时相同。各阶段耗时保存在配置目录的 `startup-performance.json`。

修复了资源请求结束时同时调用 `Complete` 和 `Dispose` 导致的 `0x8000000E` 异常。WebView2 的 `Dispose` 已会完成请求，现只调用一次。原生 UI 异常会写入本版本配置目录的 `native-unhandled.log`；集成检查会将此类异常或非正常退出判为失败。

界面对照使用同一份游戏数据、皮肤和主题，分别启动原 Electron 0.2.2 与原生版：

- 两者默认客户区均为 1360×860，设备缩放为 1。

- 启动卡 379,666 个像素中，超过 RGB 噪声容差的差异为 638 个，约 0.168%。未声称不同浏览器引擎能逐像素一致。

全部界面沿用原版源码，未另画一套相似界面。不同 DPI、多显示器、系统材质以及完整公网多人联机仍需补充环境检查。测试使用独立 .qa 配置与客户端副本，正式版账号、设置及声明记录未改动。

运行包体积以 release/SIZE.json 为准；系统 WebView2、.NET、Java、Minecraft 和按需下载的内容不计入安装包。当前仍包含独立 Node.js 兼容引擎。
