# 0.3.2 本地内存测试

以下测试发生在公开发布前，使用独立本机配置。正常界面继续使用原有 Vue、Three.js 和 WebView2；低占用模式会销毁浏览器控件，使其子进程真正退出，恢复时重建原界面。

## 使用

设置 → 行为与登录 → 低占用模式 → 立即进入。可另外勾选“游戏启动后自动进入低占用模式”，默认不勾选。自动进入后收起到系统托盘，双击托盘图标或右键选择“恢复主界面”返回。手动进入时提供原生小窗口，也可收起到托盘。

低占用时不提供下载、皮肤编辑、资源管理等界面功能。已有 Minecraft 进程继续运行；已有或正在连接的 FRP、VoxLink、虚拟局域网服务保留。没有活动核心连接时，兼容业务后端也会休眠。恢复界面后功能重新可用。存在下载、安装或文件任务时暂缓进入；未保存皮肤、布局编辑和偏好写入也会阻止切换。自动请求等待任务完成，游戏退出或用户关闭自动选项后停止等待。“启动后关闭启动器”和自动低占用选项互斥。

## 本机结果

同机、独立 QA 配置、逐个运行对照。数值按 MiB（1,048,576 字节）取整；私有提交量是进程的 PrivatePageCount，工作集是整个启动器进程树 WorkingSetSize 相加，会重复计算共享页，不等同于任务管理器的私有工作集。

| 场景 | 私有提交量 | 进程总工作集 |
| --- | ---: | ---: |
| 原 0.3.1 首页，默认背景 | 304 MiB | 469 MiB |
| 原 0.3.1 首页，20 张自定义大图 | 372 MiB | — |
| 优化后首页，相同 20 张自定义大图 | 294 MiB | — |
| 低占用，无活动联机核心 | 约 30 MiB | 约 48 MiB |
| 低占用，保留持续 TCP 核心连接 | 约 72 MiB | 约 117 MiB |

低占用的两组私有提交量均低于 100,000,000 字节。保留核心时的总工作集仍超过 100 MB；正常完整界面也没有达到 100 MB。真实 EasyTier、FRP 子进程、房间人数、游戏目录和显卡驱动会改变结果，不承诺所有联机组合低于同一上限。Minecraft 本身不计入启动器内存。

测试确认 WebView2 浏览器、渲染器及 GPU 子进程退出；持续 TCP socket 和核心后端 PID 在切换及恢复期间不变。自动切换使用 QA 模拟的游戏 running 事件，不代表已经完成真实 Minecraft 启动后的双机联机验证。游戏内体验和实际公网联机仍待用户验收。

## 实现与复测

- 轮播只预载当前和下一张；隐藏时释放预载对象。
- 默认背景使用独立缩略图，自定义 PNG/JPEG 缩略图有磁盘缓存；图片授权后用文件流传输。
- 图片尺寸检查不再整图编码为 PNG/Base64；解码图像缓存限制为 8 MiB / 32 项，皮肤资料缓存限制为 4 MiB / 8 项。
- 方块注册表按需解压；最小化后释放可重建缓存，降低 WebView2 内存目标。此目标是尽力而为，不保证硬上限。
- 低占用使用控件 Dispose 释放 WebView2，无活动核心时停止业务后端；没有通过强行清空工作集来制造测量结果。

```powershell
node native-launcher/scripts/measure-memory.cjs --label current
node native-launcher/scripts/measure-memory.cjs --label custom-gallery --gallery-stress
node native-launcher/scripts/verify-low-memory.cjs
```

测试配置、采样进程明细和截图在本机 `.qa/`，不随公开源码分发。首次恢复会重新创建浏览器，耗时取决于设备和缓存。Microsoft 的低内存目标行为见 [WebView2 MemoryUsageTargetLevel](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2.memoryusagetargetlevel)。
