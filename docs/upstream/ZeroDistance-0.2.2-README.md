# ZeroDistance

面向 Windows 的 Minecraft Java 桌面启动器，基于 [YUN-SAN3/KAMUCL](https://github.com/YUN-SAN3/KAMUCL) 开发，参考 Modrinth 的实例与资源管理体验，以及 PCL2 的版本安装流程。

当前版本：**0.2.2 Preview**。这是可构建的 Electron + Vue 3 + TypeScript 应用，拥有真实的本地文件、游戏安装、账号和联机后端。

## 使用

打包成品位于 `release/`，提供两个 Windows x64 版本：`ZeroDistance-0.2.2-Setup.exe` 是可选择安装目录、创建快捷方式和卸载的安装程序；`ZeroDistance-0.2.2-windows-x64.zip` 为免安装版，完整解压后直接运行 `ZeroDistance.exe`，请保留随附文件和文件夹。两者都包含完整启动器运行组件。游戏运行还需要与版本匹配的 Java，可在设置中自动识别或下载。

首次打开启动器会显示[使用声明与免责声明](docs/DISCLAIMER.md)。显示满 3 秒后才能主动同意，切换到其他窗口时暂停计时；拒绝或关闭窗口会退出。完成同意前不进入启动器或加载账号、目录扫描、联机服务。相同声明只需同意一次；声明内容更新后重新提示，可在设置的关于页面随时查看。

1. **账号管理**：选择 Microsoft 正版登录，通过微软设备代码页面授权；或创建离线账号。微软登录需拥有 Minecraft Java 版的账号，离线账号使用本地身份。
2. **安装游戏**：在“我的游戏 → 版本下载”中，选择 Minecraft 版本与原版、Fabric、Forge、NeoForge 或 Quilt 加载器。
3. **下载资源**：“发现资源”默认使用 Modrinth，可切换模组、整合包、资源包、光影和数据包。资源按实际版本与加载器匹配，下载显示真实进度。模组需要先安装兼容实例。
4. **导入整合包**：首页点击“导入整合包”，选择 `.mrpack` 或兼容的整合包 `.zip`；也可将文件拖入窗口。
5. 选择账号和游戏，在启动台点击“启动游戏”。每个实例可独立设置 Java、内存和资源目录。

## 0.2.2 的体积优化

投影方块注册表改为一份无损 Brotli 数据，主进程与工作线程共用，构建时逐字节核对原始 JSON。ZIP 使用标准 Deflate 的三轮压缩，可直接通过系统解压；没有移除照片、3D 预览、视频组件或兼容性文件。体积主要受内置 Electron 运行时影响，代码层面的收益有限，详见 [体积审查](docs/SIZE_AUDIT.md)。

`npm run audit:size` 对已生成的 Windows 成品输出代码、依赖、素材、运行时、许可与压缩贡献，结果保存在 `.qa/size-audit/`。`npm run test:size` 和 `npm run test:size:desktop` 验证全部方块数据以及真实工作线程的投影读取、转换。

## 0.2.1 的修复

- 社区资源的 Minecraft 版本筛选使用独立、实色浮层，避免被卡片的遮罩和模糊层挡住。支持选项点击、方向键、Esc、点击外部及外部滚动关闭。
- “我的游戏 → 版本更多菜单 → 局域网验证设置”可一键关闭当前版本作为局域网主机时的正版验证，也可恢复默认。下次启动该游戏生效，无需另装联机模组；离线联机提示直接打开这个设置，并保留“不再提示”。
- 本地资源与子菜单统一为 13px 字号，以缩进、连接线和分组背景表达层级。侧栏加宽到 132px，避免截断名称；展开、收起不改变文字大小。

## 游戏与资源管理

- 游戏库显示实例目录的实际占用，不重复计入共享库、资源与共享游戏目录。目录过大、无法完整读取时标注“≥”，可点击大小重新计算。
- 版本下载按 1.20、1.21、26.3 等版本系列折叠。大小是客户端、当前平台依赖库与资源的完整下载估算，已缓存文件会复用；Java、加载器和模组另计。资源下载窗口显示具体文件大小，整合包清单大小不等于最终安装大小。
- 启动台显示运行中的游戏版本和进程数量。同一版本多开会分别计入进程数量；重新打开启动器也会恢复仍在运行的进程状态。
- 离线账号可在“本地资源 → 皮肤”选择 64×64 PNG，保存经典或纤细模型。游戏内显示需要 [CustomSkinLoader](https://github.com/xfl03/MCCustomSkinLoader)，页面可按所选游戏版本查找下载。配置在下次启动时同步，仅本机可见；已有 CSL 来源会保留，修改前备份配置。没有模组加载器的原版实例需先安装兼容加载器。
- MOD 前置检查默认显示为右下角后台任务。可随时展开或最小化，切换页面不会中断；检查完成后仍需确认安装。
- “应用背景”控制启动器页面的底色或图片，与启动台照片轮播分开。五套主题为远山、白昼、落日、云间、星夜，沿用旧配置键以兼容升级。

## 和好友联机

先启动相同版本和兼容模组配置的游戏。房主进入单人世界，在暂停菜单中选择“对局域网开放”，记下端口。

| 方式 | 准备 | 使用 |
| --- | --- | --- |
| FRP 内网穿透 | 樱花穿透账号、访问密钥、可用节点和隧道 | 在“零距联机 → FRP 内网穿透”配置本地游戏端口并启动隧道；好友使用映射地址加入 |
| VoxLink | 双方均打开启动器，服务端可达 | 创建或加入六位房间码；成功后将页面给出的地址填入游戏“多人游戏 → 直接连接” |
| 虚拟局域网 | 首次下载并校验官方陶瓦工具 | “零距联机 → 虚拟局域网”通过基于 EasyTier 的陶瓦引擎创建或加入房间，按页面的地址与状态操作 |

连接状态来自实际后端。隧道账号权限、外部服务可用性、防火墙与双方网络会影响连接结果。离线账号进入零距联机会提示主机验证设置，可勾选“不再提示”；不再推荐额外的联机模组。

作为房主，可在“我的游戏 → 版本更多菜单 → 局域网验证设置”中一键关闭，退出并重新启动该游戏后，再开放局域网世界。内置补丁只在启动所选版本时加载，不修改游戏 JAR，也不改变独立服务端或他人服务器的验证方式。独立服务端仍由房主设置 `server.properties` 的 `online-mode`。关闭验证后无法核实玩家身份，请仅邀请可信好友；切换验证方式可能影响 UUID，先备份存档。若版本不兼容，会提示失败并保留原设置。

## 源码运行

需要 Node.js 22 或更新版本、npm、Java 17+（用于构建内置局域网补丁），Windows 构建还使用系统 .NET Framework 编译器。可通过 `JAVA_HOME` 或 `ZERO_DISTANCE_BUILD_JAVA` 指定构建用 Java。构建脚本从 Maven Central 下载并校验固定版本的 ECJ 编译器，仅用于开发，不随软件分发；补丁生成 Java 8 字节码。

```powershell
npm ci
npm run dev
```

```powershell
npm run build
npm start
npm test
npm run test:startup
npm run test:fixes:desktop
npx tsc --noEmit
npm run license:check
npm run dist:win
```

如果 npm 跳过 Electron 下载，运行 `node node_modules/electron/install.js`。已有构建可双击根目录的 `启动 ZeroDistance.cmd`。

`npm test` 运行 ZeroDistance 当前的核心和图库回归检查，`npm run test:upstream` 保留上游完整历史测试入口（含上游专用 UI 和素材断言）。

`npm run test:desktop`、`npm run test:fixes:desktop` 使用 Playwright 检查真实 Electron 窗口；需安装 Playwright，或在带有 Codex 依赖运行库的环境中执行。它们使用 `.qa/` 下的独立用户目录，不会把测试账号写入正式用户配置。`npm run test:lan` 在本机已有 26.3 与 Java 的环境中验证 JVM 补丁，并生成后续桌面测试需要的样例类；先运行它，再运行 `test:fixes:desktop`。截图和结果位于 `.qa/`。

## 数据与更新

配置、账号和日志保存在 Electron 的应用数据目录下 `ZeroDistance/`；Windows 默认游戏目录改为 `D:\ZeroDistance\.minecraft`，D 盘不可用时回退到应用数据目录下的 `.zerodistance/`。升级会保留旧游戏目录和文件，只调整原内置默认位置；手动设置的默认目录和已选择的外部目录继续保留。内部 IPC、资源协议和 Bridge MOD 的部分标识保留上游名称，以保持兼容。

启动时会在本机磁盘和桌面、文档、下载等常用位置查找 MC、minecraft、.minecraft 或“我的世界”文件夹，并登记含有效版本描述的游戏目录。查找有深度、数量与时间上限，不遍历游戏资源和系统目录；更深的目录可手动添加。“我的游戏 → 管理文件夹 → 查找本机游戏”可重新查找。登记不会搬动游戏文件；解除绑定的目录不会在下次自动登记。

启动台汇总已登记目录的游戏，兼容实例目录下的 icon.png、pack.png 和 PCL/Logo.png；本地图片缺失或损坏时显示矢量默认图标。主题切换使用 500 毫秒淡入淡出，并遵循减少动态效果设置。

皮肤 3D 预览支持行走和待机动作，可单独暂停、播放。减少动态效果时默认暂停；手动点击“行走”“待机”或播放按钮会播放预览，不修改全局设置。待机包含轻微呼吸和手臂、头部摆动。窗口隐藏时停止绘制，恢复后继续；皮肤绘制界面保持静止。

启动台图片与设置页图库共用轮播配置。默认使用用户提供并确认来自影视飓风的四张照片（其中一张来自 ARW 内嵌预览），支持排序、逐张停留时间、暂停和手动切图。全部关闭时显示主题底色。原始照片和 RAW 保留在本机，不打进应用。来源记录见 [图片说明](docs/VISUAL_ASSETS.md)。

启动动画使用 1024 像素图标与 SVG，原生与网页渲染均适配高 DPI。Windows 安装程序构建后会检查 100 MB 上限（100,000,000 字节）。ZIP 使用标准格式，完整解压后直接运行，不再包含便携自解压外壳。

当前未配置 ZeroDistance 在线更新仓库，自动更新默认关闭。配置自己的渠道前不会查询或安装 KAMUCL 的上游版本。微软 OAuth Client ID 可在设置中配置；正式发行建议使用自己获准用于 Minecraft 认证的客户端。

核心功能沿用上游实现，已做本机测试与构建；微软账号最终授权、真实 Minecraft 游戏启动、跨两台机器的联机需要实际账号、游戏和网络环境完成验收。本仓库不包含 Minecraft 游戏文件、Java 或第三方联机工具。

可选 Bridge MOD 只服务于实时 MOD 配置面板，未构建时不影响游戏安装、启动、资源下载和联机。需要该面板时，设置 JDK 17+ 并运行 `node scripts/build-bridge.cjs`，再重新构建。
