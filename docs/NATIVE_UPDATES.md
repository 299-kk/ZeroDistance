# 原生版本更新

0.3.2 引入了签名更新器；0.3.1 及更早版本需要手动安装 0.3.2 一次，才能使用后续自动更新。

0.3.4 增加了下载连接、停滞及持续低速检测和多个内置镜像。没有自定义地址时，自动模式依次尝试 GitHub、`https://gh-proxy.org/`、`https://gh-proxy.com/` 和 `https://ghproxy.net/`；连接无响应、传输停滞或持续低速（低于 256 KB/s 且按当前速度还需 60 秒以上）时切换下一来源，存在备用来源时连接超时为 10 秒、传输停滞为 15 秒，最后来源放宽到 30 秒和 60 秒；已接收的字节可续传，完整包必须通过签名清单的长度和哈希校验。填写自定义地址则只使用该镜像。0.3.3 只有单一镜像，可在更新来源选择“仅自定义镜像”并填写可用的 HTTPS 前缀后重试。镜像均为第三方，可用性因网络和运营商而异；签名与 SHA-256 校验始终启用，镜像不能改变信任来源。

## 检查与下载

设置中的更新入口优先访问 `299-kk/ZeroDistance` 的 GitHub Releases，包含签名预览版；失败后按网络来源设置尝试镜像。更新请求遵循 Windows 系统代理和绕过规则，代理无法连接时先尝试直接访问。内置镜像前缀依次为 `https://gh-proxy.org/`、`https://gh-proxy.com/` 和 `https://ghproxy.net/`，可在更新设置中填写自定义镜像替换；“仅 GitHub”不尝试镜像，“仅镜像”只使用镜像，两者均遵循系统代理。带用户名密码或非 HTTP(S) 的系统代理不会被此功能自动使用；需要认证的企业代理未验证。后台检查仍遵循自动更新与忽略版本设置，低占用模式暂停自动更新行为。

Release 附件 `ZeroDistance-update.json` 和仓库 `updates/windows-x64.json` 使用同一 RSA-SHA256 签名信封。客户端内置公钥，验证签名后解析版本、资产地址、长度和 SHA-256；镜像仅改变传输路径，不能改变信任来源。无有效更新时不替换当前版本。

更新下载完整目录 ZIP，优先 GitHub，连接超时、停滞或持续低速时切换内置镜像；支持任务取消、暂停、超时和流式校验。切换来源时可以保留已接收的部分并续传，最终完整包必须匹配签名清单。大小或哈希不匹配会丢弃新文件，保留此前已准备好的包。安装版与 ZIP 版均在正常退出后由隐藏助手替换文件，下次打开生效，无需运行安装向导。下载未完成或交接中断则在下次启动继续处理。不能只替换单个 EXE，也不能使用旧 Electron 更新包。

单次下载任务遇到中断后，每个来源最多请求四次；服务器支持字节范围时从断点继续，切换来源时也可续传。服务端忽略范围时重新下载，错误的范围声明会被拒绝；完整包仍必须通过签名清单中的长度与 SHA-256。正常退出会取消未完成任务并清理临时片段，下次检查重新开始；本版不提供跨软件重启保存下载进度。

## 应用与恢复

正常退出后将任务交给位于自身安装目录之外的更新助手；完成后保持退出，不强制重启软件或结束 Minecraft。主程序验证助手内嵌指纹，助手重新验证签名、ZIP 哈希、目录边界和版本，拒绝目录穿越、重复文件名、设备路径及链接，备份后逐项替换，最后替换主程序。ZIP 在同一只读锁定流中校验和解压。仅删除旧包清单中明确列出的程序文件；不清理游戏或个人附加文件。新配置默认开启后台静默下载，保留已有关闭选择。

应用失败会按事务日志恢复已替换文件；中断后下次启动尝试恢复日志。存在无法恢复的占用时保留记录并报告，避免循环重启。备份保存在软件数据目录的 updates 子目录，随本软件数据卸载；不是用户可选的历史版本回退列表。任意本地 ZIP 和无签名历史包不支持直接安装。

## 发布者操作

先构建、打包、完成本地测试并取得用户发布确认，再运行：

```powershell
npm run sign:native-update
```

签名脚本要求私钥与源码中固定的公钥一致，并检查私钥及专用目录权限（Windows 仅发布用户、SYSTEM 和管理员，其他系统仅拥有者可访问）。默认私钥仅保存在本机忽略目录 `.qa/publisher/update-private.pem`，可用 `ZERO_DISTANCE_UPDATE_SIGNING_KEY` 指定受保护的备份。私钥不能放进仓库、CI 日志、源码包或 Release；需另行离线备份，丢失后不能无缝签发现有客户端信任的更新。替换公钥必须规划旧客户端的过渡版本。安全边界与检查结果见 [更新安全审查](UPDATE_SECURITY_2026-10-27.md)。

签名绑定最终 ZIP 的 SHA-256，重新打包后必须重新签名。随后将同一 ZIP、签名清单、安装程序、对应源码及校验文件发布到准确的版本标签，并更新仓库 feed。源码包应包含更新后的 feed，不能包含私钥。普通构建不会自动签名、上传或创建 Release。

本地测试入口：`verify-native-update.cjs`（应用/回滚 11 组）、`verify-update-source.cjs`（来源及签名 8 组）、`verify-update-download.cjs`（流下载 6 组）、`verify-update-network.cjs`（真实 TLS、代理与切换 26 组）、`verify-update-real-fallback.cjs`（真实镜像取得已发布签名包 1 组），均位于 native-launcher/scripts。测试覆盖故障注入；真实镜像组仍属于受控测试，不代替真实 GitHub 新版本发布后的端到端升级验收。
