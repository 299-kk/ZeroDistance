# 更新功能测试 · 2026-10-27

本页保留安全加固前一轮的结果与包体哈希，对应文件已在本机 release/archive/0.3.2-before-security-20261027 留档。同日后续加固、静默退出交接及 37 项更新检查见 [更新安全记录](UPDATE_SECURITY_2026-10-27.md)，当前成品以最新 SHA256SUMS-0.3.2.txt 为准。

测试对象为发布前的本地 0.3.2 Preview。当时未提交或上传 GitHub，未覆盖用户正式安装；测试结束核对 `%APPDATA%/ZeroDistance-Native` 中账号、设置和同意记录的 SHA-256，均未变化。

## 结果

23 项检查通过，未发现需要修改运行程序的问题。

| 范围 | 结果 |
| --- | --- |
| 来源、签名、版本发现（7 项） | GitHub 优先、失败转镜像、强制来源、预览版、签名篡改和过大响应均按预期处理 |
| 下载故障（3 项） | 直连失败后镜像继续下载；损坏包被拒绝；取消关闭数据流，已验证的旧待安装包保留 |
| 更新助手（8 项） | 正常替换与备份、伪签名、包损坏、目录穿越、文件名冲突、目录链接、占用回滚及中断恢复通过 |
| 真实包集成（5 项） | 实际签名 ZIP 经更新任务下载校验，助手升级旧副本，重开界面并保留设置，在线检查及退出通过 |

集成验证使用本地真实 `ZeroDistance-0.3.2-windows-x64.zip`（39,106,916 字节，SHA-256 `c8b5aecdd8c7139bd7308f75565d5bed7d72164e409342c4637ce0fdf79b6cf9`），匹配内置发布公钥。没有临时签发假版本，也没有读取或改动发布私钥。

下载阶段将 GitHub 包请求模拟为 HTTP 503，镜像请求提供本地真实 ZIP 文件流。使用真实更新任务完成签名检查、下载校验和待安装记录，再由实际编译的更新助手升级独立 0.3.1 副本。217 个包内文件全部逐一匹配，新旧主程序备份正确；游戏目录、个人文件和配置哨兵保留。助手使用隔离 QA 参数，避免改写正式安装注册项和启动正式用户配置。

升级后实际启动 0.3.2，确认原界面、白昼主题、3072 MB 游戏内存设置和游戏目录正常读取。在“设置 → 关于与更新”实际点击“检查更新”，生产后端通过真实网络访问 GitHub，返回 `ok: true, hasUpdate: false`，界面显示“已是最新”。这符合测试时 GitHub 仅发布 0.3.1、本地 0.3.2 尚未上传的状态。

## 验证边界

本轮包含真实在线检查，但镜像下载回退是受控故障模拟，不是从尚未上传的 0.3.2 Release 下载。现有 0.3.1 没有新更新器，必须手动安装 0.3.2 一次。尚未进行“公开发布未来签名版本 → 已安装 0.3.2 自动下载 → 下次启动自动交接”的线上完整升级；本地集成直接调用更新助手，并在隔离配置中重开应用，不能将其说成已完成真实线上自动升级。用户同意发布后再追加该场景。
